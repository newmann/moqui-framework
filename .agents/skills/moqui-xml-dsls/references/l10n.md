# UI and seed localization (en / zh)

Runtime bilingual UI uses English as the **original** and
`moqui.basic.LocalizedMessage` / `LocalizedEntityField` for Chinese.
Do not put Chinese in screen XML or `MoquiConf.xml` `menu-title`.

User locale `zh_CN` falls back to `zh`, then `default`, then the original.
Use `locale="zh"` (not `zh_CN`). Do not add `locale="en"` rows for the
same English original.

Put translations in `data/{Prefix}L10nData.xml` with `type="seed"`.
Changing a label or menu string requires updating the matching
`original` (lookup is exact).

Do not duplicate strings already in `framework/data/CommonL10nData.xml`
(`Name`, `Status`, `Type`, `Description`, `Create`, `Delete`, `Add`,
`Find`, `Update`).

```xml
<!-- good: English original; zh in seed -->
<moqui.basic.LocalizedMessage original="My App" locale="zh" localized="我的应用"/>
<moqui.basic.LocalizedEntityField entityName="moqui.basic.StatusItem"
        fieldName="description" pkValue="MyStatusDraft" locale="zh"
        localized="草稿"/>
```

```xml
<!-- bad: Chinese as original; extra en LocalizedMessage -->
<moqui.basic.LocalizedMessage original="我的应用" locale="en" localized="My App"/>
<label text="我的应用"/>
```

- Screens: keep `menu-title`, `default-menu-title`, `label`, form
  `title`, `option` text, `button-text`, and `link` text in English.
  Rendering runs `localize` / `expand`.
- Status / enum display: seed English `description` (and
  `transitionName`); add `LocalizedEntityField` for fields with
  `enable-localization` and a **single** PK (`StatusItem.description`,
  `Enumeration.description`). Composite-PK entities
  (`StatusFlowTransition`) do not look up `LocalizedEntityField`;
  translate the displayed English word with `LocalizedMessage` instead.
- Service messages: `ec.message.addError` does **not** localize.
  Call `ec.l10n.localize("English message")` first. Interpolated text:
  `ec.resource.expand('Process ${key} not found', '')` so the template
  (with `${}`) is the `original`.
